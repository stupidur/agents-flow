# 字段补全询问（内容不足时）

生成 `.docx` **之前**，必须先保证 9 个字段均有可靠内容。素材不充分时**禁止**静默用 `[待补充]` 凑数后直接出文档。

## 何时视为「内容不足」

对下表每一字段判断，满足任一条即视为**缺失/不充分**：

| 字段 key | 模板标签 | 不充分判定 |
|----------|----------|------------|
| `project_name` | 项目名称 | 空、仅「客户」「对方」等泛称、无法对应具体项目/客户名 |
| `interview_purpose` | 访谈目的 | 空、或与素材完全无关的猜测 |
| `interview_time` | 访谈时间 | 空、无法解析为具体日期/时段 |
| `interview_location` | 访谈地点 | 空、且素材未提及线上/线下/地点线索 |
| `participants` | 参加人员及其联系方式 | 空、或仅有职务无姓名/无联系方式且素材里其实有 |
| `topics` | 访谈议题 | 空、或无法从素材归纳至少 1 条议题 |
| `interview_notes` | 访谈记录 | 空、或仅一两句无法支撑「访谈记录」篇幅 |
| `interview_results` | 访谈结果 | 空、或素材有结论但未写入 |
| `interviewee_suggestions` | 被访问者的建议 | 空、且素材未提及建议/诉求（可填「无」若用户确认） |

**禁止**用模糊推断冒充事实（例如素材未提地点却写「线上」）。

## 询问流程

1. 从素材提取 9 字段，标注每项状态：`已明确` / `不充分`。
2. 若存在**任一** `不充分` 字段 → **停止生成 docx**，向用户列出待补全清单。
3. 用模板标签（中文）逐项询问，一次消息里列全，方便用户逐条回复。

### 询问消息模板

```markdown
根据你提供的素材，以下字段尚无法可靠填写，请补充后我再生成 Word：

1. **项目名称**：？
2. **访谈目的**：？
3. **访谈时间**：（请给具体日期，如 2026-05-29）
4. **访谈地点**：？
5. **参加人员及其联系方式**：（姓名 + 电话/邮箱，多人请换行）
6. **访谈议题**：
7. **访谈记录**：
8. **访谈结果**：
9. **被访问者的建议**：（若无请回复「无」）

已能从素材确定的字段：
- **访谈时间**：2026-05-29（示例，仅列出已明确的项）

补充方式：可直接按编号回复，或粘贴补充段落。
```

只列出 `不充分` 的项；`已明确` 的项汇总在「已能确定」中，避免重复追问。

4. 收到用户补充后，合并进字段字典，**再次检查**是否 9 项均已明确。
5. 全部明确后，再执行 `fill_interview_docx.py` 生成 docx。

## 例外（用户明确授权时）

仅当用户**明确表示**以下之一，才允许对仍缺失的字段填 `[待补充]` 并生成：

- 「先出草稿，缺的用待补充」
- 「不知道的字段先空着」
- 「不用问了直接生成」

即使用户授权，也应在生成前简短说明哪些字段将为 `[待补充]`。

## 必填优先级（引导用户时）

若用户一次补不全，按优先级追问：

1. `project_name`、`interview_time`（影响文件名）
2. `interview_notes`（文档主体）
3. `participants`、`topics`
4. 其余字段
